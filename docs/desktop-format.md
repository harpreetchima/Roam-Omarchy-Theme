# Desktop palette and controller contract

The desktop integration is a client-local Roam developer extension, not a Chrome
extension or a local server. It runs only when the documented boolean
`roamAlphaAPI.platform.isDesktop` is true. It leaves normal Blueprint enabled and
does not use graph-data APIs or `extensionAPI.settings` persistence.

## Palette file

The exporter owns one user template:

```text
~/.config/omarchy/themed/roam-omarchy-palette.json.tpl
```

Omarchy renders it into the staged theme, then activates:

```text
~/.local/state/omarchy/current/theme/roam-omarchy-palette.json
```

The renderer receives read-only permission to the narrow **current** directory,
not HOME or the whole Omarchy configuration. On every read, reopen its `theme`
child and the fixed `roam-omarchy-palette.json` filename. Bound input to 64 KiB.
Do not use `isSameEntry` as an inode-change detector: Chromium handle identity is
path-based. No filesystem writes, arbitrary paths, network requests, or native
commands are available through the desktop adapter.

The wire shape uses the existing version-1 palette envelope:

```json
{"version":1,"type":"palette","palette":{"mode":"dark","colors":{"background":"#1e1e2e","foreground":"#cdd6f4"}}}
```

Only the existing protocol's known keys are allowed. Required `background` and
`foreground` must be six-digit hex values and mode must be `light` or `dark`.
For optional keys only, the desktop template reader may omit an empty string or
that key's exact unresolved placeholder (for example `{{ accent }}`). Omarchy's
template engine represents absent fields that way. Any other malformed value,
unknown field, extra envelope key, missing required value, or oversized input
is rejected. After omission, run the existing strict palette-message validator;
never assign raw template strings to CSS. The Chrome/native protocol itself is
unchanged and does not accept placeholders.

The initial installer snapshot is generated by a fixed absolute
`omarchy theme color --all` invocation, without a shell, filtering unknown aliases
and omitting blank optional fields before strict validation. Seed only the owned
palette filename, without applying a theme or modifying any other current file.
`--dry-run` must not execute the resolver or write files. Installation collisions
are backed up; uninstall removes only unchanged checksum-owned files. Changed
generated snapshots may conservatively remain after uninstall, which must be
documented. Do not alter Chrome's existing helper/config/ownership record.

## Shared stylesheet controller

The transport-independent controller is exported by a classic local script:

```text
globalThis.RoamOmarchyStyles.createController({ theme, protocol, onStatus, getBlocked })
```

It returns:

```text
update({ palette, stale, blocked })
reset()
suspend()
resume()
dispose()
```

`blocked` is null when eligible, otherwise a caller-chosen fixed status such as
`disabled`, `outside-app`, `not-allowed`, `disconnected`, `waiting-folder`, or
`permission-needed`. A blocked state restores owned stylesheet/root values.
The controller independently validates a supplied palette, hashes the original
Blueprint style, guards asynchronous digest races, changes only root variables
on palette updates, and never resurrects a removed or unsupported source.
Status callbacks preserve existing Chrome names (`waiting-blueprint`,
`waiting-palette`, `unsupported`, `following`, `stale`, etc.). Suspend/dispose
restore owned state and disconnect observers; disposal is idempotent.

The optional synchronous `getBlocked()` callback checks live caller eligibility.
Both transports supply it so a silent history navigation cannot beat the next
route tick or a pending digest. Check it during reconciliation and immediately
before applying a digest result; a blocked result restores owned state. Explicit
blocked states remain restrictive even if that callback reports eligibility.

Chrome transport/lifecycle/options behavior remains unchanged. Its content script
loads this controller before use; the existing 11 browser regression cases keep
their assertions and gain only the necessary fixture script loading.

The desktop build wraps the existing protocol script and shared controller in a
private scope object, not the page's real global object, and bundles finished CSS
using the existing build-time converter. Its single `extension.js` default
export provides Roam `onload`/`onunload`; no imports, CDN, service, or runtime
palette-code evaluation is needed.

The generated `onload({ extensionAPI })` forwards the extension-scoped API to the
adapter. It registers **Settings → Omarchy** through
`extensionAPI.settings.panel.create`, with exactly one `reactComponent` row.
The component uses Roam's provided `window.React` and mounts the reusable native
shadow-tree controls only while Settings is open. Unmount detaches them but
retains the local draft and leaves background polling active. Missing APIs or
failed registration leave stock Blueprint unchanged; late registration after
unload cannot start storage or polling. Roam owns removal of the registered tab.

## Desktop behavior

- Default local graph allowlist is `hosted:Sylva`. Explicit names distinguish
  `hosted:<name>` from `offline:<name>`; `*` is an explicit all-graphs opt-in.
- Store options and the approved directory handle only in uniquely named
  client-local IndexedDB, never graph settings. Do not apply a persisted stale
  palette before a fresh successful read.
- Ask for folder permission only from a real user-clicked Choose/Reconnect
  control. Query existing permission on load; never prompt automatically.
- Poll once per second only while enabled and eligible. Guard overlapping reads,
  selection races and late asynchronous work after unload.
- Brief missing-file/invalid-read gaps may hold the last valid palette with a
  stale status; after three consecutive failed reads restore normal Blueprint.
  Permission denial/revocation restores immediately and offers Reconnect.
- Provide follow, reconnect/choose, graph scope and forget-handle controls only
  inside **Settings → Omarchy**, never in a floating overlay. Do not use
  automatically persisting Depot setting rows or settings get/set. Keep the
  existing IndexedDB database/store/keys unchanged. Unload removes native
  UI/listeners/timers and restores only owned state; a disposed component must
  not remount its controls.
- Local-folder developer extensions still need a manual reload after app
  startup. Persisted folder permission and extension autostart are separate.
  No publication, normal-profile installation, or live template activation is
  authorized by merely building this code.
